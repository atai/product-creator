# Алгоритм синхронизации Prisma схемы с бизнес-объектами

## 1. Алгоритм выбора действия по умолчанию

Система синхронизации использует многоуровневый алгоритм для определения действия по умолчанию для каждой модели Prisma:

### Шаг 1: Проверка mapping (для повторных синхронизаций)

Если для модели Prisma уже существует запись в файле `.sync-mapping.json`:
- Используется **действие из mapping** как действие по умолчанию
- Система находит бизнес-объект по `businessObjectId` из mapping
- Если объект найден и действие в mapping = `skip`, статус устанавливается в `matched`
- Если объект найден и действие в mapping ≠ `skip`, статус устанавливается в `needs_matching`

### Шаг 2: Поиск существующего бизнес-объекта

Если запись в mapping отсутствует или объект по `businessObjectId` не найден, система пытается найти объект следующими способами (в порядке приоритета):

1. **Точное совпадение по имени**: поиск бизнес-объекта, у которого `name.toLowerCase()` совпадает с именем модели Prisma
2. **Нормализованное имя**: удаление префиксов/суффиксов "model" из имени и повторный поиск
3. **Поиск по ID**: поиск бизнес-объекта, у которого `id.toLowerCase()` совпадает с именем модели Prisma

### Шаг 3: Определение действия для найденного объекта

Если объект найден:
- Вычисляется **хеш структуры** Prisma модели (имя, поля с типами и опциональностью, имя таблицы)
- Вычисляется **хеш структуры** бизнес-объекта (id, поля с типами, таблицы)
- Если хеши **не совпадают** → действие = `update` (статус: `needs_matching`)
- Если хеши **совпадают** → действие = `skip` (статус: `matched`)

### Шаг 4: Новый объект

Если объект не найден ни одним из способов:
- Действие = `create` (статус: `new`)

### Шаг 5: Удаление объектов

После обработки всех моделей Prisma система находит бизнес-объекты, которые:
- Активны (`active !== false`)
- Не были сопоставлены ни с одной моделью Prisma
- **Были ранее синхронизированы** (есть запись в mapping, где `businessObjectId` совпадает с `id` объекта)

Для таких объектов действие устанавливается = `delete` (статус: `delete`)

## 2. Описание действий синхронизации

### `create` — Создать

**Когда используется:**
- Модель Prisma найдена в схеме
- Соответствующий бизнес-объект не существует

**Что происходит:**
1. Создается новый бизнес-объект на основе структуры Prisma модели
2. Генерируется уникальный ID бизнес-объекта (формат: `model.name` → `model.name`)
3. Заполняются поля: имя, описание, поля, таблицы
4. Объект сохраняется в файловой системе
5. В mapping добавляется запись: `{ modelName → { businessObjectId, action: 'create', lastSync } }`

**Результат:**
- Новый бизнес-объект создан и готов к использованию

---

### `update` — Обновить

**Когда используется:**
- Модель Prisma найдена в схеме
- Соответствующий бизнес-объект существует
- Структура модели изменилась (хеши не совпадают)

**Что происходит:**
1. Бизнес-объект обновляется данными из Prisma модели:
   - Обновляются поля (добавляются новые, изменяются существующие)
   - Обновляются таблицы (имя, колонки)
   - Сохраняются пользовательские данные (owner, lifecycle, если они были изменены вручную)
2. Объект сохраняется обратно в файловую систему
3. В mapping обновляется запись: `action: 'update', lastSync`

**Результат:**
- Существующий бизнес-объект обновлен в соответствии с текущей Prisma схемой
- Пользовательские метаданные (owner, lifecycle) сохраняются, если не были изменены в Prisma модели

**Детали изменений:**
Система определяет конкретные изменения:
- Добавлены новые поля
- Удалены поля
- Изменены типы полей
- Изменено имя таблицы

---

### `skip` — Пропустить

**Когда используется:**
- Модель Prisma найдена в схеме
- Соответствующий бизнес-объект существует
- Структура модели **не изменилась** (хеши совпадают)

**Что происходит:**
1. Бизнес-объект **не изменяется**
2. В mapping обновляется только `lastSync` (timestamp последней синхронизации)
3. Действие сохраняется как `skip`

**Результат:**
- Бизнес-объект остается без изменений
- Запись о синхронизации обновлена (для отслеживания, что объект был проверен)

---

### `delete` — Удалить

**Когда используется:**
- Модель Prisma **удалена из схемы** (больше не существует)
- Бизнес-объект ранее был синхронизирован из Prisma (есть запись в mapping)

**Что происходит:**
1. Бизнес-объект **не удаляется физически** из файловой системы
2. Устанавливается флаг `active: false` (объект помечается как неактивный)
3. Объект сохраняется с обновленным флагом
4. Запись удаляется из mapping

**Результат:**
- Бизнес-объект становится неактивным (`active: false`)
- Объект больше не отображается в списке активных объектов
- Связь между Prisma моделью и бизнес-объектом удалена из mapping
- Данные сохраняются для возможного восстановления

**Важно:**
- Удаление **не является физическим** — файл объекта остается в файловой системе
- Можно восстановить объект вручную, установив `active: true`

## Дополнительная информация

### Mapping файл (`.sync-mapping.json`)

Система хранит mapping в файле `.sync-mapping.json` в директории бизнес-объектов:

```json
{
  "User": {
    "businessObjectId": "user",
    "action": "skip",
    "lastSync": 1234567890
  },
  "Product": {
    "businessObjectId": "product",
    "action": "update",
    "lastSync": 1234567891
  }
}
```

Mapping используется для:
- Сохранения связи между Prisma моделями и бизнес-объектами
- Определения действий по умолчанию при повторных синхронизациях
- Отслеживания объектов, которые были синхронизированы из Prisma

### Определение изменений

Система использует SHA-256 хеш структуры для определения изменений:
- **Хеш Prisma модели**: имя + поля (имя, тип, опциональность) + имя таблицы
- **Хеш бизнес-объекта**: id + поля (имя, тип) + таблицы (имена)

Если хеши отличаются, это означает, что структура изменилась и требуется обновление.

### Статусы сопоставления

В таблице синхронизации отображаются статусы:

- **`new`** (Новый) — новый объект, требуется создать. Соответствует действию `create`
- **`matched`** (Сопоставлен) — объект найден и не изменился. Соответствует действию `skip`
- **`needs_matching`** (Нужно сопоставить) — объект найден, но требуется проверка изменений или обновление. Обычно соответствует действию `update`
- **`delete`** (Удалить) — объект должен быть удален (помечен как неактивный). Соответствует действию `delete`

**Важно:** Статус и действие — это разные понятия:
- **Статус** показывает текущее состояние сопоставления (отображается в таблице)
- **Действие** показывает, что будет сделано при синхронизации (можно изменить в выпадающем списке)
